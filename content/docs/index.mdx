This documentation is The Craft's knowledge base. It is written by one person, for one person, and it grows out of real work: daily sessions, experiments, and questions that refused to go away.

It is not a tutorial site. Pages appear when there is something genuine to record — a concept finally understood, an experiment that worked (or failed), a design decision and its reasoning. Nothing here is pre-filled to look complete.

## How it is organized

| Section | What belongs there |
| --- | --- |
| [Getting Started](/docs/getting-started) | How this knowledge base works: philosophy, daily practice, principles. |
| [Computer Science](/docs/computer-science) | Theory and first principles — computation, code, and the systems beneath them. |
| [Software Engineering](/docs/software-engineering) | Building and maintaining software — architecture, design, APIs, testing. |
| [Systems & Infrastructure](/docs/systems-and-infrastructure) | The same subjects in practice — Linux, containers, networking, cloud, DevOps. |
| [Cybersecurity](/docs/cybersecurity) | Fundamentals, web security, cryptography, and CTF practice. |
| [Artificial Intelligence](/docs/artificial-intelligence) | Foundations, machine learning, LLMs, AI engineering, and agents. |
| [Engineering Journal](/docs/engineering-journal) | Reflections, experiments, and reviews distilled from daily sessions. |
| [Prodigo](/docs/prodigo) | Architecture, decision records, and research for the long-term project. |
| [Resources](/docs/resources) | Books, courses, documentation, and references — indexed, never copied. |

## How it grows

1. A daily session produces raw notes in the repository's `sessions/` directory.
2. If part of that work deserves a permanent place, it is distilled into the relevant section here.
3. Sections are non-linear — there is no required reading order, only the order curiosity takes.
