This section covers the discipline of turning ideas into working, maintainable software: how systems are structured, how components talk to each other, and how correctness is verified.

The focus is on decisions and their consequences rather than tool tutorials. A note about a specific framework belongs here only when the lesson generalizes beyond that framework.

## Areas

| Area | Scope |
| --- | --- |
| `architecture` | Structuring systems — components, boundaries, dependencies, data flow. |
| `design-patterns` | Recurring solutions, when they help, and when they add noise. |
| `system-design` | Scalability, reliability, and trade-offs at the whole-system level. |
| `api-design` | Contracts between components and services. |
| `testing` | Verifying behavior — unit, integration, property-based, and everything that actually catches bugs. |

Pages appear in these areas as the subjects are actually explored. The folders are reserved, not pre-filled.
